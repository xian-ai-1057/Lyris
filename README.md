# Lyris

跟著音樂逐字亮起、自動捲動的歌詞播放器。丟一個 `mp3` 加一個同名的 `lrc` 進去就能用。

- **後端**：一支 `server.py`，只用 Python 標準函式庫，不用 `pip install` 任何東西
- **前端**：一頁式介面，無框架、無 CDN、離線可用

## 快速開始

```bash
git clone <this-repo> && cd Lyris

# 1. 把歌丟進 media/（檔名要一樣）
#    media/告白氣球.mp3
#    media/告白氣球.lrc

# 2. 開起來
python3 server.py --open
```

瀏覽器打開 <http://127.0.0.1:8000> 就好了。

不想用預設資料夾的話：

```bash
python3 server.py --media ~/Music/歌單 --port 9000
```

| 參數 | 預設 | 說明 |
| --- | --- | --- |
| `--media` | `./media` | 曲庫資料夾，會連子資料夾一起掃 |
| `--port` | `8000` | 連接埠 |
| `--host` | `127.0.0.1` | 想讓同網段的手機也能連，改成 `0.0.0.0` |
| `--open` | — | 啟動後自動開瀏覽器 |

新增歌曲不用重開 server，重新整理頁面就會出現。

### 懶得開 server 也行

直接用瀏覽器打開 `web/index.html`，再把 mp3 / lrc / zip **拖進視窗**就能播。
（瀏覽器安全限制的關係，這個模式讀不到 `media/` 裡的檔案，也沒地方存檔，只能靠拖曳。）

## 上傳一包 zip

不想手動搬檔案的話，開曲目清單，最下面就是上傳區：把打包好的 zip 拖進去，
或點一下選檔案。解開後會放進 `media/<zip 檔名>/`，馬上出現在曲單裡。

```
告白氣球.zip
├── 告白氣球.mp3
├── 告白氣球.lrc
└── cover.jpg        ← 整包共用一張封面也可以
```

- 只收音檔、`.lrc` / `.txt`、圖片，其它的（`.md`、`__MACOSX/`…）會直接略過
- 整包只包在一層外殼資料夾裡的話會自動脫掉，不會多一層
- 檔名是 Big5 / GBK 的舊 zip 也讀得出來，不會變亂碼
- 同名資料夾不會互相蓋掉，會自動變成 `名字-2`
- 單包上限 600 MB

沒有開 server 的時候，zip 會直接在瀏覽器裡解開來播（用內建的 `DecompressionStream`，
一樣不需要任何函式庫），只是不會存檔。

## 自己做 lrc（打時間軸）

右上角的「製作歌詞」，兩步驟：

1. **準備**：挑一首曲庫裡的歌（或選本機音檔），把歌詞貼進去，一行一句
2. **打軸**：按空白鍵開始播，之後每唱到一句就按一下空白鍵，時間就釘上去了

| 鍵 | 動作 |
| --- | --- |
| `空白鍵` | 停著時＝開始播；播著時＝標記這句並跳到下一句 |
| `Backspace` | 退回上一句，清掉它的時間並倒帶重來 |
| `Enter` | 播放／暫停 |
| `←` `→` | 前後 3 秒 |
| `Esc` | 關掉打軸器（打到一半的東西會留著） |

沒有鍵盤的話按「標記這句」按鈕也一樣。

打歪了不用重來：每一行都可以 `−` `+` 微調 0.1 秒、`✕` 清掉重打，點時間就跳到那個位置聽。
整體都慢半拍的話，把「微調」填 `-200` 這種負數，輸出時會整份往前挪。

放慢速度（0.5×／0.75×）打快歌會準很多，播放速度不影響記下來的時間。

弄完按「下載 .lrc」；想先聽聽看對不對，按「套用到播放器」就會直接拿去播，
確認沒問題再下載，把檔案放到 mp3 旁邊（同檔名）就完成了。

貼歌詞的時候：空白行會變成間奏（顯示呼吸點），已經有時間軸的 lrc 直接貼也行，
舊的時間軸和 `[ti:]` 這類標籤會自動拔掉。選曲庫裡本來就有歌詞的歌，還會自動幫你載進來。

## 檔案怎麼放

```
media/
├── 告白氣球.mp3
├── 告白氣球.lrc          ← 同檔名就會自動配對
├── 告白氣球.jpg          ← 選用。沒有的話會去讀 mp3 內嵌的封面
├── 晴天.txt              ← 只有純文字歌詞也可以，會靜態列出不做同步
└── 周杰倫 - 晴天.mp3     ← 「歌手 - 歌名」的檔名會自動拆開
```

歌詞優先吃 `.lrc`；同名只有 `.txt` 的話就當成沒有時間軸的純文字歌詞平鋪顯示。

封面的尋找順序：mp3 內嵌的 ID3 圖片 → 同名圖檔 → 同資料夾的 `cover.jpg` / `folder.jpg`。
三個都沒有就用歌名生一組漸層色，不會開天窗。

音檔格式跟著瀏覽器走，`mp3` / `m4a` / `wav` / `flac` / `ogg` / `opus` 都收。

## 功能

- **逐字填色**：中文逐字、英文逐詞地跟著唱到的位置亮起來
- **平滑捲動**：目前這句固定在畫面偏上的黃金位置，其餘依距離漸層淡出與模糊
- **點歌詞跳轉**：點任何一句就跳到那個時間點
- **手動捲動不打架**：你一滑動就暫停自動捲動，4 秒後自動接手，也可以按「回到播放位置」
- **配色跟著封面走**：從封面抽兩個主色，背景光暈、進度條、高光都跟著換
- **間奏呼吸點**：沒有歌詞的段落顯示三顆逐一亮起的點，知道還要等多久
- **雙語歌詞**：同一個時間軸的第二行會自動當成翻譯，縮小顯示在下方
- **拖曳播放**：mp3 / lrc / 封面 / zip 直接拖進視窗
- **zip 上傳**：一包丟進去自動進曲庫
- **打時間軸**：按空白鍵就能做出自己的 lrc
- **系統媒體鍵**：耳機線控、鎖定畫面的上一首／下一首都能用

## 鍵盤快捷鍵

| 鍵 | 動作 |
| --- | --- |
| `空白鍵` / `K` | 播放／暫停 |
| `←` `→` | 倒退／快轉 5 秒 |
| `↑` `↓` | 音量 |
| `N` / `P` | 下一首／上一首 |
| `M` | 靜音 |
| `L` | 開關曲目清單 |
| `Esc` | 關閉曲目清單 |

## 支援的 LRC 寫法

一般的時間軸：

```lrc
[ti:歌名]
[ar:歌手]
[offset:+500]

[00:12.50]第一句歌詞
[00:16.20]第二句歌詞
```

還吃得下這些變化：

| 寫法 | 行為 |
| --- | --- |
| `[00:12.50][01:20.00]同一句` | 副歌重複，會展開成兩句 |
| `[00:12:50]` | 冒號式的百分秒 |
| `[00:12.50]` 後面接空白 | 當成間奏，顯示呼吸點 |
| `[00:12.50]原文` + `[00:12.50]譯文` | 同時間軸的第二行當翻譯 |
| `<00:12.50>Every <00:13.10>word` | 增強型逐字時間軸，會照它走 |
| `[offset:+500]` | 整體提早 0.5 秒 |
| 完全沒有時間軸（或給 `.txt`） | 當成純文字歌詞平鋪顯示，不做同步 |

時間軸亂序、超過一小時、`CRLF`、有 BOM 都沒問題。

## 放到網路上給別人用（Vercel）

部署不需要後端。`build.mjs` 會把 `web/` 跟 `media/` 併成一份 `dist/`，
順便把 `server.py` 的 `/api/tracks` 先算好存成靜態 JSON，前端拿到的東西跟本機一模一樣。

1. 到 <https://vercel.com> 用 GitHub 帳號登入
2. **Add New… → Project**，選這個 repo，按 **Import**
3. 設定畫面什麼都不用改，直接 **Deploy**（`vercel.json` 已經寫好建置指令與輸出目錄）
4. 一分鐘後拿到 `https://<專案名>.vercel.app`

之後每次 push 到 `main`，Vercel 會自動重新建置與部署。想在本機看部署後的樣子：

```bash
node build.mjs        # 產生 dist/
```

### 要讓線上版一打開就有歌

**`media/` 裡的檔案必須進版控**，Vercel 才看得到——它是從 GitHub 拉程式碼去建置的，
你本機的檔案它讀不到。所以 `.gitignore` 不能再排除 `media/`。

這代表**你放進去的音樂會跟著 repo 一起公開**（repo 是 public 的話任何人都能下載），
請只放自己有權散布的檔案。不想公開就把 `media/` 留在 `.gitignore` 裡，
線上版會是空的，讓訪客自己拖檔案進去播。

### 線上版跟本機版的差別

| | `python3 server.py` | Vercel |
| --- | --- | --- |
| 曲庫來源 | 每次請求都重掃 `media/` | 建置時掃一次，寫進 `dist/api/tracks.json` |
| 新增歌曲 | 丟進 `media/`，重新整理就有 | 要 commit + push，等重新部署 |
| 上傳 zip | 存進 `media/` | 瀏覽器當場解開來播，不會存檔 |
| 內嵌封面 | 會挖出 mp3 的 ID3 圖片 | 不會，請放同名圖檔（否則顯示漸層） |
| 拖曳播放、打軸器 | 一樣 | 一樣 |

`server.py` **不會**跟著部署：Vercel 跑的是無狀態的 serverless function，
沒有可以長期存檔的磁碟，所以線上版的上傳只能是「當場播、不留存」。
要有大家都能寫入的共用曲庫，得自己找一台常駐機器跑
`python3 server.py --host 0.0.0.0`，並注意下面那段安全提醒。

## 專案結構

```
vercel.json        # 部署設定：建置指令與輸出目錄
build.mjs          # 把 web/ + media/ 併成 dist/，並先算好靜態版的 /api/tracks
server.py          # 掃曲庫 / 送音檔（支援 Range）/ 送 lrc / 挖 ID3 封面 / 收 zip
web/
├── index.html
├── styles.css
├── unzip.js       # 瀏覽器端解 zip（離線模式用）
├── maker.js       # 打時間軸、輸出 lrc
└── app.js         # LRC 解析、逐幀同步、主色抽取、上傳
media/             # 你的歌
dist/              # build.mjs 的產物（已被 .gitignore 排除）
```

後端刻意做得很薄：它只負責「找檔案」「把 bytes 吐出來」跟「把一包 zip 解到 media/」，
LRC 解析、時間同步、配色、打軸全部在前端做，所以前端拿掉 server 也還能靠拖曳運作。

## 一點安全提醒

上傳是寫檔案的操作，而預設只綁 `127.0.0.1`，也就是只有這台電腦連得到。
真的要改成 `--host 0.0.0.0` 讓手機也能連的話，請確定那是你信任的網路——
同網段的人都能上傳東西進你的 `media/`。

擋掉的部分：路徑一律洗過並限制在 `media/<資料夾>/` 之內（`../` 逃不出去）、
只寫入音檔／歌詞／圖片這幾種副檔名、單包 600 MB 與解開後 2 GB 的上限。
